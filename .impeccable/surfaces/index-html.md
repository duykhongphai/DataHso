# DataHso data browser

Mode: Operate. The visitor needs to locate a game record, read exact fields, copy an ID, or open
the raw JSON quickly. The page must remain useful on mobile and when the first collection has not
finished.

## Direction contract

**THESIS:** A route board through the HSO catalog: every category is an explicit destination and
the data grid is the manifest at that stop. It refuses both the generic hero-dashboard and a
decorative fantasy landing page.

**OWN-WORLD:** Keep DataNro's light, compact, high-information family, but reserve saturated guild
yellow for wayfinding bands and selected destinations. Soot-black type, cool stone surfaces,
hairline rules, square black pictogram fields, and 12–14px corners create a recognizable HSO
instrument even with all copy removed.

**STORY:** The visitor immediately sees data freshness and available destinations, chooses a
catalog, searches or sorts it, then opens one record in a persistent detail drawer. Raw JSON and
copyable IDs remain one action away; missing files explain whether collection is still running.

**FIRST VIEWPORT:** A sticky yellow destination band spans the top. Beneath it, a compact status
rail shows last update and live record count, followed immediately by search/sort controls and a
responsive data grid. The first real records—not a marketing hero—occupy most of the viewport.

**FORM:** Lead structure 7 from surface seed `3c888123`: sticky route bands plus a content grid.
Category changes use one restrained split-flap-style message swap; mobile keeps only the current
destination and opens the rest as a horizontal, keyboard-scrollable route strip.

**FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review, the
verdict, DESIGN.md, and every shipping raster carrying its provenance
